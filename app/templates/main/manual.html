Getting started

What you are looking at right now.

  1. Start the local server. Run python run.py and open http://127.0.0.1:5000/ on the same computer. PowerAble does not need the internet.
  2. Create an account or sign in. Pairing an outlet requires a signed-in account so the outlet can be linked to you. Passwords are stored only as hashes.
  3. Check the connection banner. “Waiting for hardware” means the Flask server is running but no verified outlet telemetry has arrived.
  4. Register an outlet. Open /devices/pair or tap the Add button in the mobile dock, then scan the label or type the printed credentials.
  5. Read the summary cards and outlet cards. Each registered outlet keeps its own measurements, relay state, energy limit, and future schedules.

Accounts, pairing & camera

How to register a real outlet, especially from a phone.

Stage 2
  1. Install the label. The installer runs flask --app run.py provision-outlet --device-id PA-ESP32-0001. The command prints the pairing code once and writes a QR image under instance/qr/. Only a one-way hash of the code is stored.
  2. Open a secure address on the phone. Mobile browsers only allow the camera on https:// pages or localhost. On a computer, run python scripts/serve_https.py and open the printed https://<your-computer-ip>:5443/ address on the phone. The helper creates a self-signed local certificate, so the phone shows a one-time warning you must accept. A plain http://192.168.x.x:5000 address cannot use the camera.
  3. Allow camera permission. Tap Start camera and accept the browser prompt. The rear camera is requested first. Flashlight and camera switching appear only when the device and browser report support.
  4. Scan or type the label. If the camera is unavailable, open Enter device details manually and type the device ID and pairing code. The same server checks apply.
  5. Confirm the device. The confirmation sheet shows the device ID and type. Nothing is registered until you tap Register This Outlet.
  6. Register once. Registration links the outlet to your account and consumes the code. The same QR label cannot be used again. Registering does not put the outlet online.
Security rule Behaviour
QR contentsFormat version, public device ID, one-time pairing code. No Wi-Fi password or permanent secret.
Code storageOnly a scrypt hash is kept; the plaintext code is shown once during provisioning.
Single useA successful registration clears the code immediately.
Rejected statesInvalid, revoked, already-claimed, and malformed labels are refused by the server.
OwnershipOnly the signed-in owner can read the outlet. Other accounts receive “not found”.
Camera feedFrames are decoded locally in the browser. Only the QR text is sent to your Flask server.
  • Stop the camera with the Stop button, or by leaving the page. The browser releases the camera.
  • Flashlight is used only when the active camera exposes a torch capability.
  • Manual entry works over plain HTTP and needs no camera permission.

Wi-Fi provisioning for the ESP32-S3 is a separate process that is not implemented yet. Pairing a label never sends Wi-Fi credentials, and a registered outlet stays “waiting for first reading” until real telemetry arrives.

Understanding readings

Zero can mean two very different things.

Field Meaning Initial state
VoltageSupply voltage in volts.0.00 V · awaiting data
CurrentCurrent drawn by the appliance in amperes.0.00 A · awaiting data
Active PowerReal power in watts.0.00 W · awaiting data
Power FactorRatio of real power to apparent power.0.00 · awaiting data
Total EnergyLifetime energy counted by the outlet.0.000 kWh · awaiting data
Session EnergyEnergy counted since the current session began.0.000 kWh · awaiting data

A reading of 0.00 W with a valid timestamp means the outlet is genuinely drawing no power. A reading of 0.00 W marked “awaiting data” means no verified measurement exists. The interface always distinguishes the two.

Relay controls

Commands must be confirmed by the hardware.

Clicking a toggle will eventually send a command to the ESP32-S3 through the Flask API. The switch will not change to ON just because it was clicked. It changes only after the outlet reports its confirmed relay state.

  • Unknown — no confirmed relay state has been received.
  • OFF — the hardware confirmed the relay is open.
  • ON — the hardware confirmed the relay is closed.

At this stage the switches stay disabled because no outlet has reported a relay state yet.

Energy limits and auto cutoff

Safety features need trustworthy measurements.

Each outlet can have a maximum session energy. When the verified session energy reaches that limit, PowerAble will request an OFF command and record the event. If energy readings are stale, missing, or invalid, the cutoff will not silently guess — it will report that it could not act.

The input and Auto Cutoff switch are placeholders until Stage 5.

Schedules

Local time-based ON/OFF operations.

The Scheduling page will let you choose an outlet, an ON or OFF action, and a local time. Schedules will be stored in SQLite. For offline reliability, critical schedules are planned to be mirrored to the ESP32-S3 so they can run even if the Flask server is temporarily unavailable.

Scheduling is still a design preview. Saving is implemented in Stage 5.

Connection states

How to tell what the system really knows.

  • Waiting for dataThe server is running, but no verified telemetry has arrived.
  • OnlineA recent, authenticated message was received from the device.
  • StaleThe last reading is too old to be trusted. Values are marked as outdated.
  • DisconnectedNo recent communication. Commands are rejected or queued only if explicitly supported.

Troubleshooting

Common local-development checks.

All values are still zero. Is that a bug?

Not necessarily. Until the ESP32-S3 sends verified telemetry, zero is the correct placeholder and each card says “awaiting data.” Check the connection indicator before assuming a measurement.

The page will not open.

Confirm the Flask server is running with python run.py and open http://127.0.0.1:5000/. Check the PyCharm terminal for errors.

Why are the relay switches disabled?

Hardware control is not implemented yet. Enabling a switch without a confirmed hardware response would be misleading.

The camera will not start on my phone.

Mobile browsers require HTTPS or localhost for camera access. If the page address starts with plain http:// and is not localhost, use python scripts/serve_https.py, accept the self-signed certificate warning, and reload. You can always fall back to manual entry.

My pairing label is rejected.

Codes are single-use. A label is also rejected when it is malformed, belongs to a revoked outlet, or was already registered. Ask the installer to provision a new label for that device.

Does PowerAble need the internet?

No. Flask, SQLite, CSS, JavaScript, and the planned ESP32-S3 communication all run on the local network. No CDN or cloud service is used.

Safety notes

This is a thesis prototype, not a certified electrical product.

  • Do not touch mains wiring while the circuit is energized.
  • Use a properly rated relay module and enclosure for any real load.
  • Never rely on the web interface as the only safety disconnect.
  • Test with a safe, low-power load before connecting appliances.
  • Follow your local electrical code and institutional safety rules.
